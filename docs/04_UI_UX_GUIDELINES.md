# Synora — UI & UX Guidelines

## Purpose

This document defines the permanent design language of Synora.

Every page, component, and future feature must follow these guidelines to maintain a consistent user experience.

---

# Design Philosophy

Synora should feel:

* Modern
* Clean
* Fast
* Professional
* Student-friendly
* Minimalistic

Avoid unnecessary complexity.

---

# Color Theme

Primary Background

* Dark Slate

Accent Color

* Blue

Supporting Colors

* White
* Light Gray
* Soft Green (Success)
* Orange (Warning)
* Red (Error)

Future themes (Light Mode) may be added later.

---

# Typography

Headings

* Bold
* Clear
* Easy to scan

Body Text

* Medium weight
* High readability

Avoid decorative fonts.

---

# Layout Rules

Every page should have:

1. Navigation Bar
2. Main Content
3. Optional Sidebar (feature dependent)
4. Footer (future)

Spacing should remain consistent across the application.

---

# Navigation

Main Navigation should always provide access to:

* Dashboard
* Task Marketplace
* Borrow Hub
* Opportunity Network
* Campus Guide
* Profile
* Logout

Future modules should be added without redesigning the navigation.

---

# Dashboard

Dashboard should act as the user's control center.

It should eventually display:

* Quick statistics
* Recent activities
* Notifications
* Shortcuts to modules
* Active tasks
* Borrow history
* Recommended opportunities

---

# Cards

Synora primarily uses card-based layouts.

Cards should have:

* Rounded corners
* Consistent padding
* Hover effect
* Clear title
* Short description
* Optional action buttons

---

# Forms

All forms should be:

* Simple
* Clearly labeled
* Mobile friendly
* Consistently spaced

Validation messages should be displayed below the relevant field.

---

# Buttons

Button hierarchy:

Primary

* Blue
* Filled

Secondary

* Outline

Danger

* Red

Disabled

* Gray

Button styles should remain consistent across all pages.

---

# Icons

Use simple, recognizable icons.

Avoid excessive decoration.

Icons should improve usability rather than replace text.

---

# Animations

Animations should be subtle.

Examples:

* Fade in
* Hover effects
* Smooth transitions
* Loading indicators

Avoid excessive animations that reduce performance.

---

# Responsive Design

The platform must support:

* Desktop
* Laptop
* Tablet
* Mobile

Desktop remains the primary target during initial development.

---

# Accessibility

Pages should:

* Maintain sufficient color contrast.
* Use readable font sizes.
* Support keyboard navigation where practical.
* Avoid relying on color alone to communicate important information.

---

# Future UI Enhancements

Potential future additions:

* Light mode
* Theme customization
* Dark mode improvements
* User personalization
* Accessibility options

These enhancements should build upon the existing design system rather than replacing it.

---

# AI Development Rule

No AI assistant should redesign completed pages without explicit approval from the project owner.

Existing UI components should be extended, not replaced, unless a redesign has been approved.

Consistency is more important than novelty.
